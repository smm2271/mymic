# BUG-001: Windows background audio timing

## Evidence and root cause limits

The user's foreground near-zero/background approximately 25% observation is a reported reproduction, not a measurement generated by these scripts. Redirected stdout and an independent process did not fix the user's reproduction. This investigation cannot programmatically control native terminal focus/minimization, so it does not claim that exact visibility-dependent cause has been conclusively traced.

The original code used a Tokio 10 ms interval with `MissedTickBehavior::Skip` in the control/audio loop. Sequence and generator sample time advanced only when a tick was processed. The untouched Release executable delivered 5355 packets in 60.008 s (89.238 packets/s), with zero authenticated sequence gaps. This confirms a slow source timeline can produce an audio deficit without UDP loss. The console's actual visibility was unverified. No original TX scheduling instrumentation existed, so its scheduling P99 is unavailable.

The fix separates source pacing from control, uses absolute deadlines and native high-resolution waitable timers, and registers only the Windows TX thread with MMCSS Audio. A waitable timer alone was insufficient during the initial long run. Multimedia scheduling substantially improved the measured timer results. This supports a Windows wake/scheduling contribution; it does not prove that `timeBeginPeriod` or window occlusion is the sole OS root cause. Period-1 experimentation was not consistently better and is not enabled by default. Engineering builds and other desktop activity occurred during comparative runs, so these are not perfectly isolated randomized experiments.

## Measurements

The machine's exact Windows version, raw reports, CPU readings and observed counter values are preserved in `artifacts/bug-001-results.json` and its referenced artifacts. All transport tests use Release and authenticated UDP loopback.

| Run | Duration | RX packets/s | Observed gaps | Interpretation |
|---|---:|---:|---:|---|
| Untouched v0.5 | 60 s | 89.238 | 0 | Slow generated timeline; focus unverified |
| Isolated current-policy comparison | 60 s | 99.626 | 0 | Clock drift 231.54 ms; not untouched old binary |
| Absolute sleep | 60 s | 99.596 | 25 | Deadline skips visible in header sequence |
| Absolute + period-1 | 60 s | 90.226 | 587 | Build-load interference; no causal visibility claim |
| Waitable without MMCSS | 60 s | 97.363 | 159 | Native timer alone not sufficient in this run |
| Waitable + MMCSS, hidden/redirected | 60 s | 100.012 | 0 | 6001 TX sent = 6001 RX; no skips/send errors |

The successful 60-second MMCSS run had send interval P99 10.848 ms, scheduling delay P99 1.111 ms, max scheduling delay 1.516 ms and final clock drift 0.443 ms. No burst replay was used. The initial 600-second waitable-only run had RX 96.860 packets/s, scheduling P99 12.473 ms and 1763 operational underruns. The final 600-second MMCSS run measured RX 99.985 packets/s, 255.962 kbps payload, send interval P99 10.440 ms, scheduling delay P99 0.606 ms (max 2.221 ms), and 16 callback/operational underruns over ten minutes. Core CPU was 1.643% of one core and Simulator 1.013%. Remaining callback underruns are explicitly retained rather than hidden.

A 10-second WASAPI system-output loopback capture found a dominant 440.0 Hz tone and zero quiet 10 ms blocks out of 1000. This is an automated shared-output observation, not isolated process capture or human listening. It cannot establish continuity throughout a ten-minute run.

## Reproduce automated tests

Run from repository root, with Rust and Node on PATH:

```powershell
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --release --workspace
npm.cmd --prefix web/angular test
npm.cmd --prefix web/angular run build -- --configuration production
python tests/integration.py
python tests/telemetry-integration.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/host/run.ps1
python tests/timing-benchmark.py --mode waitable --seconds 60 --output artifacts/timing-repeat.json
python tests/timing-benchmark.py --mode waitable --seconds 60 --loss-every 20 --output artifacts/timing-loss5.json
python tests/background-audio-benchmark.py --seconds 600
python tests/bug-001-report.py
```

The raw benchmark owns ports 41400/41402 and implements authenticated pairing independently of Core/audio. The pipeline benchmark owns HTTP 18085/UDP 41500–41502, opens the default playback device, uses a low-gain sine and collects actual Core metrics/CPU. Both stop their own processes on completion. Keep unrelated audio and heavy builds off during controlled repeats. Standard deviation/visibility effects must not be inferred from a single run.

The remaining occasional callback starvation means zero-interruption acceptance is not claimed. Background rate stability is measured; exact focus-conditioned parity and complete audible continuity require these manual checks.
